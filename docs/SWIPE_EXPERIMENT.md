# X Swipe Navigation 内蔵版比較実験

実験ブランチ: experiment/xtend-native-swipe

目的: WXT拡張機能版に比べて、Xtend本体でXスワイプを管理した方が操作品質と保守性が向上するか調べる。現時点では拡張機能を廃止せず、保存データやZIPも削除しない。

## 比較する2モード

- 通常Debug起動: インストール済みの拡張機能を使用。WebView標準の戻るジェスチャーは有効。
- Debugに --xtend-swipe-back-disabled を付けて起動: インストール済みの拡張機能を使ったまま、WebView標準の戻るジェスチャーだけ無効にする。
- Debugに --xtend-embedded-swipe を付けて起動: 同じWXTビルドのJavaScriptをアプリリソースから WKUserScript で読み込む。インストール済みのSwipe拡張だけは実行せず、標準の戻るジェスチャーも無効にする。
- その他の拡張機能は両方で引き続き動作する。Releaseでは起動引数にかかわらず通常動作。
- 内蔵JSは x-swipe-navigation/.output/chrome-mv3/content-scripts/content.js から取った検証用のスナップショット。本採用時はソースと配布経路の一本化が必要。

## 検証内容

1. 同じXログイン状態、同じタイムラインを使用して両モードを比較する。
2. ホームタブ左右往復、左端からのメニュー開閉、縦スクロール、短いスワイプのキャンセル、投稿操作・画像・動画への干渉を検証する。
3. 左端ジェスチャーがWebViewの「戻る」に奪われないか、戻るジェスチャー無効化に実用上の問題がないか確認する。
4. XCUITestの証跡画像と可能なら実機で指への追従・描画の乱れを比較する。

同じJavaScriptを実行するため、JS内のタブ・メニュー認識とアニメーション方式に性能上の違いはない。主要な検証差分はネイティブ戻るジェスチャーとの競合。

合格条件: 少なくとも現行版のスワイプ品質を維持し、メニューと戻る動作の競合を改善する。副作用とソースの二重保守コストを評価した後に採用を判断する。

## 2026-10-24 検証結果

- Debug Simulatorビルド成功。
- EmbeddedSwipeConfigurationTests 2件成功。内蔵スクリプトの登録と拡張機能版の二重実行防止を確認。
- iPhone 17 Pro / iOS 26.4 / ログイン済みXで3モードのXCUITestを実行し、各テスト完走（計3件）。
- 保存したスクリーンショットを確認。内蔵モードと通常モードでは、ホームタブの左右往復と左メニューの開閉・復帰を確認。戻るジェスチャーだけ無効にした第3モードでも、タブ切り替えとメニュー表示を確認。
- XCUITest自体のアサーションはWebView存在確認であり、切替成否はスクリーンショットの目視確認。実iPhoneの滑らかさ、指追従性、スクロールとの競合、戻る操作の副作用は未検証。

現時点の判断: アプリ内蔵にしても画面上の操作結果に明確な優位性はない。戻るジェスチャーの調整だけなら独立拡張機能を維持したまま本体側で可能。拡張機能の廃止は保留とする。
