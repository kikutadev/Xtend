# Xtend 現行仕様

Xtendは、iPhoneの`WKWebView`でXを閲覧し、Xの操作ジェスチャーと対応するChrome拡張機能を利用するための**X専用アプリ**です。汎用ブラウザや任意のChrome拡張機能を動かす環境ではありません。

## 対応環境と基本構成

- iOS 18以降、iPhone向け。プロジェクト名・画面表示名は`Xtend`。
- Web表示は`WKWebView`。Xホームは`https://x.com/home`を開く。
- User-AgentはWebKitの標準値をベースに、Xへのアクセス時にSafari起動用URLへ転送されないよう`Safari/604.1`識別子だけを付加する。Safariのバージョンは独自生成しない。
- ログイン状態とWebサイトデータは`WKWebsiteDataStore.default()`に保存し、アプリの再起動後も利用する。
- アドレスバー、複数タブ、ブックマーク、ダウンロード管理などの汎用ブラウザ機能は提供しない。

## 初回起動と拡張機能

- X向けManifest V3 `content_scripts` を持つChrome拡張機能は、ID・拡張名ごとの登録を必要とせずにChrome Web StoreのURL、GitHubの最新Release、またはZIPから追加できる。にゃっとランドforXのみ既存の専用アセット処理を維持する。

### にゃっとランドforX（推奨・任意）

- 対応するChrome Web Store拡張機能IDは`kchlmbffcbaambfigakeiamkhgacemng`のみ。
- 初回起動時と設定画面に、にゃっとランドforX、X Ad Hider、X Timeline Filter、x-home-anchorのおすすめ一覧を表示する。公開ReleaseまたはChrome Web Storeから取得できる前3件は「追加」ボタンで既存のURLインストール処理へ渡し、追加済み・取得処理中はボタンを無効にする。配布ZIPのみのx-home-anchorはダウンロード先を開き、ZIPインストールを案内する。各候補の配布元ページも開ける。初回画面と設定画面のインストール操作は同じ部品を使い、URL欄は空欄から始まる。利用者がURLを入力するかおすすめの「追加」を押した場合のみインストールできる。導入せずにXを閲覧でき、導入後も一覧を表示して利用者がXへ進む。
- Chrome Web Storeから取得する場合は、Googleの配信先からCRX3を取得し、署名・拡張機能ID・配信元を検証する。展開後、Manifest V3、必要なスクリプト・権限なども検証する。
- ローカルZIPからのインストールもできる。ZIPは拡張機能のファイル構成を検証するが、**Chrome Web Storeの開発者署名は検証できない**。
- インストール先はアプリ専用の`Application Support/Extensions/kchlmbffcbaambfigakeiamkhgacemng/`。
- 新しいパッケージを検証してから既存のファイルを置換し、置換に失敗した場合は旧版へ戻す。更新中に終了し旧版が退避された場合は、次回の起動時に旧版の復旧を試みる。
- にゃっとランドの必須スクリプト、popup.html、画像インデックスと参照packも導入前に検証し、欠損パッケージを拒否する。
- にゃっとランドのCRX、展開済みコード、画像、音声はXtendのリポジトリや`.app`に同梱しない。

### x-home-anchor（任意）

- Xホームで新着表示後の閲覧位置を保つための補助拡張機能。初期状態では未インストールで、必須ではない。
- 作者の公開ソースをビルドした`dist/`のZIPを、設定画面から利用者が選択して導入する。現時点でGitHub Releasesは公開されておらず、リポジトリ内の`release/`に配布ZIPがある。TypeScriptを含むGitHubのソースZIPをそのまま実行しない。
- ZIPの`manifest.json`とビルド済み`content.js`などを検証し、`Application Support/Extensions/x-home-anchor/`へ保存する。
- インストール済みの場合だけ、`x.com`で独立したJavaScript実行領域（`XHomeAnchor.Content`）に読み込む。
- x-home-anchorのコードや配布ZIPはXtendに同梱しない。ZIPの配布元の真正性は保証しない。

## X閲覧と画面操作

- X・TwitterのページではWebView内での閲覧とログイン遷移を許可する。
- 利用者が明示的に開いたX以外へのHTTPSリンクはSafariへ渡す。認証に必要な自動HTTPSリダイレクトはWebView内に残す。
- Xのページが新しいウィンドウを開こうとした場合、XのURLは同じWebViewで、外部HTTPS URLはSafariで開く。
- Xホームの左右スワイプでタイムラインタブを切り替え、左端からX自身のメニューを開き、メニュー内の左スワイプで閉じる。この操作はXtend標準機能であり、Chrome拡張機能のインストールは不要。タブとメニューはXの既存UIを利用し、縦スクロール・投稿・メディア・入力操作を優先する。
- X上ではWebView標準の戻るスワイプを無効化し、Xの画面にある戻る操作を利用する。X以外の認証ページ等ではWebViewの戻るジェスチャーを維持し、必要に応じてネイティブの戻るボタンを表示する。
- Xの各ポストのリポストボタンを約500ms長押しすると、押したポスト自身の引用一覧（`/i/status/<ID>/quotes`）をXのSPA画面として同じWebViewで開く。ページ全体の再読み込みはしない。短いタップは元のリポストメニューを維持する。移動・マルチタッチ・ページ切替では長押しをキャンセルし、引用ポスト内の別の投稿を誤参照しない。戻る操作はX自身の画面階層に従う。
- 旧X Swipe Navigation拡張機能は実行せず、ZIPの導入・更新・削除UIも提供しない。既存のファイルは自動削除せず、読み込み対象・設定一覧から除外する。
- Googleなどの外部OAuth認証は埋め込みWebViewの制約により成功を保証できない。Xのユーザー名・メールアドレス・電話番号を使うログインを想定する。
- Webコンテンツのプロセスが終了した場合はページを再読み込みする。短時間に異常終了が繰り返される場合は無制限に再読み込みせず、再試行を案内する。ページ読み込み失敗時もエラーと再試行操作を表示する。

## 設定・更新

- 通常のX閲覧時はXのプロフィールメニュー下部に`Xtendの設定`を表示する。初めてログイン済みのXホームを表示したときは、左上のプロフィールアイコンを暗転オーバーレイで強調（ラベルは「← 設定」のみ）し、左メニューを開いたら実際の`Xtendの設定`項目へ強調を移す。設定を開く、メニューを閉じる、または「×」で案内を終了し、端末に記録して再表示しない。投稿画面・画像表示・その他の画面では案内を出さない。ログイン画面とXtendが検知したページ読み込みエラー時のみ右上の設定ボタンを表示し、投稿・画像・動画などのX操作画面には重ねない。設定画面ではインストール済み拡張機能の一覧・削除・Xページの再読み込み、および初回画面と同じURL入力によるインストール・ZIPインストール・おすすめ一覧からの追加・`にゃっとランドの設定`を利用できる。
- Web Storeからの手動インストール・更新は対応する拡張機能を共通経路で処理する。**自動更新はしない**。
- GitHubのリポジトリURL、HTTPSクローンURL（`.git`付き）、SSHクローンURL（`git@github.com:owner/repo.git`、`ssh://git@github.com/owner/repo.git`）、ReleasesのURLを入力すると、GitHub APIの最新の公開済みReleaseを問い合わせ、アセットから拡張機能ZIPを一意に選び、ダウンロードして既存のZIP検証・更新処理へ渡す。GitHubの自動生成ソースZIPは候補に含めない。複数の候補から特定できない場合はエラーとする。
- Private GitHubリポジトリではGitHubのContents読み取り権限を持つ任意のトークンを使用できる。入力したトークンはインストール成功後に端末内Keychainへ保存し、設定画面から削除できる。XのCookieやChrome拡張機能へ渡さない。GitHubのRelease取得は利用者がインストール操作をしたときだけ実施し、バックグラウンドでの自動確認・自動更新は行わない。
- 設定画面のインストール済み拡張機能には「更新を確認」ボタンを表示する。GitHubから導入した拡張機能は保存済み取得元を使用し、既存のZIP・Web Store経由の拡張機能は初回にクローンURLを登録して確認する。確認したReleaseのタグとインストール済みバージョンを比較し、古い場合のみ「最新版を取り込む」を選べる。取得元URLは端末内に保存するが、定期確認・無人更新はしない。更新ZIPが別の拡張機能だった場合はインストールせず、旧版・ID・設定を保つ。
- ZIPからの導入はManifest V3とX向けスクリプト、参照リソースを検証し、拡張機能IDごとに保存する。既存のにゃっとランドとx-home-anchorの個別検証は維持する。他のインストールを上書きしない。
- 拡張機能の追加・更新・削除に成功した場合は、設定画面を閉じると変更を自動反映する。設定画面で複数回変更してもWebViewの再構築は1回にまとめ、失敗・キャンセル時は再構築しない。手動の再読み込みボタンは補助操作として残す。
- 拡張機能の構成変更でWebViewを再生成する場合は、閲覧中のURLだけを引き継ぐ。Xtend独自のスクロール位置・表示ポスト・戻る履歴・投稿下書き・動画再生状態の復元は実装しない。Xのタイムラインは通常の再読み込みと同様に更新される。x-home-anchorが提供するX内部の閲覧位置補助とは別機能。
- 読み込めない拡張機能はその拡張機能のみ無効化し、正常な拡張機能とXの閲覧を継続する。設定画面には異常のある拡張機能も表示し、削除・再インストールで修復できるようにする。
- 設定画面を持つ拡張機能には一覧で設定ボタンを表示し、`options_ui.page`（別タブ指定を優先）、`action.default_popup`、または従来の`popup.html`を、その拡張機能専用WebViewに表示する。HTMLがない場合やパスが不正な場合は設定ボタンを出さない。設定内容は端末内で拡張機能ごとに保存し、実行中の拡張機能へ通知する。

## 拡張機能の実行範囲

- 共通の拡張機能ホストが、拡張機能IDごとにJavaScript実行領域、保存領域、リソース配信を分離する。X上のコンテンツスクリプトとCSS、基本的な`chrome.storage`等を実行する。Chromeのservice workerや未実装API、全拡張機能の動作は保証しない。にゃっとランドの画像パック応答のみ既存の専用処理を維持する。
- にゃっとランドのContent Scriptsはインストール済み`manifest.json`の順序、JavaScript実行領域（MAIN／ISOLATED）、読み込みタイミングに従ってX／Twitter上で実行する。
- モバイル版Xにデスクトップ向けプロフィールリンクが存在しない場合、にゃっとランドの本人別履歴のため、専用の `NyattoMobileXAdapter` を当該拡張機能の実行領域にのみ適用し、開いたアカウントメニューで本人のハンドルを確認できた場合に限り互換リンクを補完する。通知や投稿の著者から本人を推定しない。ログアウト・アカウント切替時、または表示中のアカウントメニューを確認できない場合には既存の識別状態を無効化する。履歴自体の保存は共通の `chrome.storage` を使う。
- ブラウザ上で必要な`chrome.runtime`、`chrome.storage.local`、`chrome.storage.sync`等のAPIを限定的に提供する。`storage.sync`は**端末内の保存領域**であり、Chromeアカウントとの同期ではない。
- `chrome.storage.local` / `chrome.storage.sync` は、どの拡張機能もIDと保存領域を分離したファイルへアトミックに書き込み、書込完了後に成功と変更通知を返す。既存の `UserDefaults` 保存値はファイルがない場合だけ移行用に読み込み、次回更新でファイルへ保存する。ファイルが空の場合も古い値を復活させない。にゃっとランド固有のストレージ保存処理は作らない。
- 拡張機能の画像アセットはインストールされたパックデータから必要な範囲を読み出す。任意のChrome拡張機能やChrome APIすべてへの対応は保証しない。
- 設定画面の拡張機能リソースは拡張機能IDごとに隔離した専用の`xtend-extension://`スキームで扱い、任意のWebサイトがその権限を使うことは許可しない。

## セキュリティ・ライセンス

- ZIPインストールではファイル数・展開サイズ・パス・シンボリックリンクを検証し、不正な展開を防ぐ。
- XのCookieや認証情報をソースコードや配布ビルドに含めない。アプリ独自の分析サーバー、アカウント管理、テレメトリーは設けない。
- アプリ独自コードのライセンスはMIT。ZIPFoundationのライセンス文はルートの`LICENSE`に収録する。外部から取得した拡張機能は各提供元の権利・ライセンスに従う。
- 実機向け署名情報は利用者が自身のXcodeで設定する。リポジトリに署名鍵・プロビジョニングファイル・端末データを入れない。

## 検証の要点

実装の確認では、次を区別する。ビルド成功やコード上の確認だけで、X上の実動作まで確認したことにはしない。

1. クリーンなSimulatorビルド、未インストールからのWeb Store導入、ZIP導入、インストール失敗時の保護。
2. インストール後のX表示、ログイン状態の維持、再起動、設定の保存と反映。
3. Xホームでのにゃっとランドの表示・機能と、必要なChrome互換APIの動作。
4. x-home-anchorを導入した場合の、実際の「新着ポストを表示」操作後の閲覧位置維持。
5. 外部リンクのSafari遷移、認証画面、WebView標準User-Agentでの動作。
6. 拡張機能不要でホームのタブ左右往復・左メニュー開閉・キャンセルができ、縦スクロール・投稿操作やWebViewの戻るジェスチャーとの競合がないこと。

一般利用者向けの実機インストール方法は[README](../README.md)、開発用のSimulatorビルド・Xcodeでの実機実行・ZIP作成手順は[開発者向けドキュメント](DEVELOPMENT.md)を参照する。実機を含むPhase 2の未完了検証と残作業は[Phase 2計画](PHASE2_PLAN.md)で管理する。
