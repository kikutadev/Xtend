# ADR 0001：拡張機能の障害隔離と自動反映

- 状態：Superseded（[ADR 0002](0002-simple-extension-reload.md)）
- 決定日：2026-10-23
- 関連仕様：[SPEC.md](../SPEC.md)
- 実装・検証計画：[PHASE2_PLAN.md](../PHASE2_PLAN.md)

## 背景

初回版は拡張機能の初期化が失敗するとXの表示・設定画面の表示まで阻害する場合があった。また拡張機能の追加・削除を反映する手動再読み込みで、閲覧中のURL以外の状態が失われていた。拡張機能の便利さよりもXを閲覧できることを優先する。

## 決定

- 壊れた拡張機能だけを読み込まず、健全な拡張機能とXの閲覧を続行する。拡張機能ファイルや保存設定は自動削除しない。修復は設定画面から行う。
- 拡張機能の追加・更新・削除に成功した後、設定画面を閉じるとWebViewを一度だけ再構築し、新しい構成を自動反映する。失敗・キャンセルした操作だけの場合は再構築しない。
- 再構築前のURLとスクロール位置の保存・復元はXtend本体が担い、x-home-anchorに依存させない。x-home-anchorはX内部の「新しいポストを表示」操作を補助する独立機能。
- popup内の保存設定の変更は拡張機能ID別の通知で伝え、設定値変更のたびにWebViewを破棄しない。

## 採用しなかった案

- **破損時にXtend全体を停止する**：利用者がXを閲覧できず、設定画面からの修復もできなくなる。
- **変更反映を手動再読み込みに任せる**：設定画面での操作完了と実際の反映が一致せず、操作忘れも発生する。
- **戻る履歴・投稿の下書き・動画再生位置まで完全復元する**：WebKitやX内部の状態に依存し、Phase 2の安定化目的に対して過大。将来必要性に応じて別途検討する。

## 影響・トレードオフ

自動再読み込みによって未送信の投稿や再生状態が失われる可能性がある。そのため変更をまとめ、再構築を最小回数にする。Xのタイムラインが更新されると同じスクロール位置を完全には復元できない。復元不能な場合でもブラウザーを使用不能にしないことを優先する。
