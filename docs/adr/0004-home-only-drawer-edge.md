# ADR 0004: Xホームだけ左端スワイプをメニューに使う

- 決定日: 2026-10-25
- 状態: Accepted
- 置換: [ADR 0003](0003-built-in-x-navigation.md)

## 背景

Xtendの標準スワイプ統合では、X上のWebView標準の履歴「戻る・進む」を一律無効にした。ホームの左メニューとの競合はなくなったが、投稿詳細・通知・プロフィールなどからスワイプで戻れず、元のブラウザ操作が退化した。

## 決定

- Xtend標準のタブ切り替えとXメニューは引き続き本体機能とし、別のWXT拡張機能を起動しない。
- `https://x.com/home` と `https://twitter.com/home` のみ、WebView標準の履歴スワイプを無効にし、左端からXメニューを開く。メニューを閉じる動作は維持する。
- ホーム以外のXページでは左右端にiOSの`UIScreenEdgePanGestureRecognizer`を置き、WebViewの`goBack()` / `goForward()`に渡す。XのSPA画面ではWebKit標準の戻る・進むジェスチャーだけでは画面端操作を認識できなかったため、同一WebView上で標準の履歴ジェスチャーは重複実行させない。左端スワイプでXメニューは開かない。メニューはXのプロフィールボタンから開ける。
- 画面中央のタブ切り替えはホーム・通知・プロフィールなどで従来どおり維持する。ホーム以外では左右両端から始まるタブジェスチャーをJavaScript側で受け取らず、履歴操作との競合を防ぐ。
- Xの画面内遷移はページ読込イベントなしにURLが変わるため、WKWebViewのURL変更を監視して切り替える。URLで判定できない場合に無理にメニュー操作を推測しない。

## 不採用案と影響

- X全ページで履歴スワイプを無効にする案は、閲覧時の戻る操作を失うため不採用。
- WebKit標準の履歴スワイプだけを全ページで有効にする案は、ホーム左メニューと競合し、ホーム以外でもXの実画面でスワイプを認識できなかったため不採用。
- JavaScriptで独自の履歴操作を再実装する案は、WebViewとXの履歴を二重管理するため不採用。

WebKitに履歴が存在しない場合は戻る・進むジェスチャーも動作しない。拡張機能構成の変更でWebViewを作り直す場合、以前の履歴は復元しないという既存方針は維持する。
