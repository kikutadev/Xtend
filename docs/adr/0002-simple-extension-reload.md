# ADR 0002：拡張機能変更時の再読み込みを簡素化する

- 状態：Accepted
- 決定日：2026-10-24
- 置き換える決定：[ADR 0001](0001-phase2-extension-recovery.md)
- 現行仕様：[SPEC.md](../SPEC.md)

## 背景

Xtendは拡張機能の追加・更新・削除時に新しいWebView構成を反映するため、必要な場合のみWebViewを作り直す。ADR 0001ではWebView再生成後のスクロール位置と表示中のポストを独自に復元する方針だったが、Xのタイムラインは再読み込みで内容・順序が変わり、同じスクロール量では同じ投稿に戻れない。DOM位置の採取、再試行、画面比較の維持コストに対して効果が限定的だった。

## 決定

- **拡張機能の構成変更が成功した場合のみ**設定画面を閉じるタイミングで変更をまとめて反映し、必要に応じて新しいWebViewを生成する。従来どおり異常拡張機能のみ隔離し、健全な拡張機能とX閲覧を継続する。
- 再生成するときは現在のURLを引き継ぐ。**スクロール量、可視ポストのアンカー、戻る履歴、編集中投稿、メディア状態はXtend独自には復元しない。**
- 拡張機能内の設定値変更は既存の通知機構で扱い、WebViewの再生成を不要にする。
- X内部の新着表示に伴う位置調整は、必要な人が使うx-home-anchor拡張機能の責務とする。

## 採用しなかった案

- 独自DOMアンカーとスクロール量を取得し、画面再描画後に繰り返し復元する案：同じポストへの復元を保証できず、保守が複雑になる。
- 拡張機能構成変更を反映しない案：有効化・削除がXに反映されず、設定画面の表示と実際の動作が食い違う。
- すべての設定値変更でWebViewを再生成する案：必要ない再読み込みを増やす。

## 影響

拡張機能の構成変更時には、通常の再読み込みと同じようにタイムラインが先頭付近へ戻る場合がある。これを仕様として許容し、不要な再生成の削減、ログイン状態の保護、変更反映の確実性を優先する。
