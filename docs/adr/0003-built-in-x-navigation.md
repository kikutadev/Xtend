# ADR 0003: Xの操作ジェスチャーをXtend本体の責務とする

- 決定日: 2026-10-24
- 状態: Superseded by [ADR 0004](0004-home-only-drawer-edge.md)

## 背景

Xtendの目的を「XのWeb版をネイティブXアプリに近い操作で利用できるX専用アプリ」とする。既存のX Swipe Navigationは独立WXT拡張機能としてZIP導入されるため、Xtend側の戻るジェスチャー、Xページ側のタッチ操作、拡張機能側の動作を個別に調整する必要があった。

## 決定

- ホームのタイムライン左右スワイプとXの左メニュー開閉を、インストール不要のXtend標準機能にする。
- WebViewおよびOSのジェスチャー調整はSwiftで管理する。Xのタブ・メニュー認識と既存のクリック操作・アニメーションは、Xtend管理の独立JavaScriptで維持する。Xの非公開APIや通信の再実装はしない。
- 独立WXT拡張機能のインストール・更新・実行・削除UIを取り除き、二重にジェスチャー処理を動かさない。
- 他の独立拡張機能（にゃっとランド、x-home-anchor）は引き続き個別導入とする。
- 旧Swipe拡張機能の保存ファイルを自動削除しない。読み込まず設定画面にも出さない。Xのログイン状態と他の拡張機能の保存領域は維持する。

## 不採用案と理由

- 独立WXT拡張機能のまま維持: PCのChromeでも利用できるが、アプリ操作の責務が外部パッケージに分散する。
- ジェスチャーを全面Swiftに移植: XのDOM識別と描画を結局WebView上で行うため、通信・同期の複雑さに見合う改善を確認できない。
- 独立版と内蔵版を設定で切り替える: 製品上の二重経路と競合管理を残すため採らない。

## 影響と検証

XのDOM変更に追従する保守はXtend本体が担う。WebView標準の画面端「戻る」操作と左メニューの競合を防ぐため、Xページ上のWebView標準の戻るスワイプは無効にする。X内の戻る操作はX自身のUIを利用する。外部の認証ページなどではWebViewの戻るジェスチャーを残す。

実機の操作品質、縦スクロール・投稿や画像/動画のジェスチャーとの競合、表示の滑らかさはSimulatorとは分けて検証する。
